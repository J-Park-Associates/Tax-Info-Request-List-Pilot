# requirements.txt and requirements-build.txt pin what the tracker imports by
# name. They do not pin what those packages pull in - pdfminer.six under
# pdfplumber, cryptography and charset-normalizer under pdfminer.six - and
# pip takes the newest of each on the day of the build. So two builds of one
# commit were not the same build (the build of 09/17 froze pypdfium2 5.13.0
# against a pinned 5.11.0). "Build App.bat" installs with -c constraints.txt,
# and tests/test_build.py fails when a package's BUILD-INFO.txt froze differs
# from the version here.
#
# This is `pip freeze` of the build's own virtual environment (Windows,
# Python 3.14). Change a pin in requirements*.txt and this file together:
# rebuild, copy the new BUILD-INFO.txt's list here, run the suite.
#

# installs this tree where the build does not: numpy on the floor's
