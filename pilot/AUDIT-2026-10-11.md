# Security and design audit, 2026-10-11

Run by Jason's instruction after the Mac port landed (SPEC-mac jobs 1, 2, 5,
6, 7 and 8 merged on `claude/zealous-faraday-hw5sga`, head `44792c9` before
this audit). The audit was done in this session, not through the build loop;
the cleanup it made is one commit, gated by the affected tests, ruff and the
map check. Nothing here was run on a Mac.

## 1. The answer

The repository is in good shape for a buyer's security review and for the
next engineer. No unsafe call was found in the Python or the shell: no
`shell=True`, no `eval`, no pickle, every subprocess takes a list, every SQL
statement is parameterised or built from the module's own constants, every
pip install is hash-checked, and the only network code in the tree is the
lock tool's talk to PyPI and OSV, which no scheduled or app path reaches.
The Electron shell is locked down (context isolation, no node integration,
sandbox, a content-security policy, window-open and navigation denied, every
path the renderer may open checked against the API's own list and refused
when it is a symbolic link). The GitHub workflows pin their actions by hash,
declare their permissions, and never run on a pull request from a fork.

The cleanup removed two functions nothing but the suite called, one dated
prompt file, two wrong folder names, and fixed one ordering fault in the lock
release on POSIX that the job 5 review had left for later. The map tool now
knows shell scripts, so the six scripts a buyer would read first are nodes.

removed.
